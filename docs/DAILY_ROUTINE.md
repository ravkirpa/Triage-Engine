# Outbound SDR agent: daily routine
Identity: **Outbound SDR agent** for TankhaPay (unified global payroll + HRIS for multi-entity companies). Technology only. Compliance is **global**, never India-only. Every valid lead is emailed regardless of intent. Send only the campaign emails from `due`; never send anything else and never email anyone not in the database.

1. `python -m sdr report`. If there are no leads, stop and tell the user to run `/lead` with a database.
2a. **Bounces:** search `in:inbox newer_than:3d (subject:undelivered OR subject:undeliverable OR subject:"delivery status" OR subject:"mail delivery" OR subject:failure OR from:mailer-daemon OR from:postmaster)`; the sender can be any mail system, so also open each hit with `get_thread` and read the `Final-Recipient:` line. For every permanent failure (5.x.x status) run `python -m sdr suppress <email> --reason "hard bounce <code>"` and never email that address again.
2b. **Auto-replies and cover contacts:** for every out-of-office or "no longer working here" auto-reply from a lead, read the full message with `get_thread` and find any email address it names as cover, an alternate or an HR contact (ignore IT or support lines and the sender's own address). Run `python -m sdr cover <original email> <cover email> --reason "<why>"` for each; this adds them as a new lead with the same company and bottleneck. Then send them a Day-1 email at once, with the exact `subject`, `body` and `htmlBody` from `python -m sdr due` (or render step 1), and record it with `python -m sdr sent <cover email> 1 --ref thread:<id>`. Do not add the same address twice.
2. **Replies:** with the Gmail connector, search for replies from each lead email (`search_threads`, then `get_thread`). For each new reply run `python -m sdr reply <email> "<text>" --subject "<subject>" --id <message id>`. A reply stops that lead's cadence.
3. **Due emails (send):** run `python -m sdr due` (day 1, then a follow-up every 2 days: day 3, 5, 7, 9, 11, 13, ...; at most 80 emails a day in total: due follow-ups first, then up to 40 new first emails with whatever room is left). The user has authorised sending, so send each one with `send_message` to that email with the exact `subject`, `body` and `htmlBody` (the subject is fixed for every email; for step 2 and later, find the first email's thread with `search_threads` (`in:sent to:<email> subject:"Simplifying payroll and HR management"`) and pass its id as `replyThreadId` so the follow-up lands in the same thread), and `includeSignature: true` (the Gmail signature carries the logo and the exact Calendly link; never add either to the body or alter them). Run `python -m sdr sent <email> <step> --ref <message id>` only after a send succeeds. Before sending, skip anyone whose reply was logged in step 2.
Follow-up framework (step 2 onwards, one part per follow-up): follow-up 1 Problem, 2 Insight, 3 Proof, 4 Solution, 5 Next step; after follow-up 5 with no reply it loops back to follow-up 1 (Problem). `due` already renders the right body; just send it. A reply stops the whole sequence.
3b. **If you cannot send** (the send tool is unavailable, the Gmail sign-in has expired, or a send fails): do NOT send. Create a Gmail draft (`create_draft`, same `subject`, `body`, `htmlBody`, `includeSignature: true`; follow-ups in the first email's thread) for each remaining due email, run `python -m sdr drafted <email> <step> --ref <draft id>` for each, and tell the user the drafts are waiting for approval. Never mark a draft as sent. When the user approves, send each draft with `send_message` using its `draftId`, then run `python -m sdr approve`. If Gmail cannot be reached at all, just report that nothing was done; the next run picks up everything still due.
4. **Triage:** for interested/question/referral replies, draft a suggested response (as a Gmail draft) that nudges the lead to book via the Calendly link in the signature, or to share a time.
5. **Summary** to the user: replies by category, drafts created today, leads needing attention, and a reminder to review and send the drafts.
